Platform Adapter
The answer to "why does cmd/server exist AND cmd/localapi exist?" — and how the frontend works across all surfaces with one codebase.

This is the most important concept for frontend developers joining the project. Read this before touching any code in frontend/src/.

The Core Problem

The same React codebase needs to run in three different environments:

🌐 Browser (Web)

The Go engine runs as a .wasm file inside the browser tab. No HTTP server involved. Call Go functions directly via JS globals.

🖥️ Desktop (Wails)

The Go engine runs in the same native process as the window. Call Go methods via Wails IPC bridge (window.wails.*).

🔌 Local API

The Go engine runs in a separate process on localhost:7428. Call it via standard HTTP fetch().

The Solution: IPlatform Interface

A TypeScript interface that all three adapters implement. React components only ever call this — they never know which surface they're on.

// frontend/src/platform/types.ts
interface IPlatform {
  run(document: string, format: string): Promise<RunResult>
  parse(document: string, format: string): Promise<TraCtlSpec>
  validate(document: string, format: string): Promise<ValidationError[]>
  layout(document: string, format: string): Promise<DAGLayout>
  runRequest(req: RequestDef): Promise<RequestResult>
  inferDeps(document: string): Promise<DepMap>
  exportWorkflow(document: string): Promise<string>
  defaults(): Promise<EngineDefaults>
}

How Each Adapter Implements It

Calls the Go functions registered as JavaScript globals by cmd/wasm/bridge.go. The engine runs inside the browser's WASM thread — no network request.

// platform/web/index.ts
class WebPlatform implements IPlatform {
  async run(document: string, format: string) {
    // window.tractl is registered by cmd/wasm Go binary
    const json = await window.tractl.run(document, format)
    return JSON.parse(json) as RunResult
  }
}

Calls Go methods via Wails IPC. The engine runs in the same process as the native window — no HTTP, no WASM loading.

// platform/desktop/index.ts
class DesktopPlatform implements IPlatform {
  async run(document: string, format: string) {
    // Wails IPC — calls cmd/desktop/app.go App.Run()
    const json = await window.wails.Run(document, format)
    return JSON.parse(json) as RunResult
  }
}

Standard HTTP fetch() calls to localhost:7428. The engine runs in a separate Go process.

// platform/localApi/index.ts
class LocalApiPlatform implements IPlatform {
  async run(document: string, format: string) {
    const res = await fetch('http://localhost:7428/api/v1/workflows/run', {
      method: 'POST',
      body: JSON.stringify({ document, format })
    })
    return res.json() as Promise<RunResult>
  }
}

Surface Detection

// platform/index.ts — detects which surface and exports the right adapter
function detectPlatform(): IPlatform {
  if (typeof window.wails !== 'undefined') {
    return new DesktopPlatform()        // Wails desktop
  }
  if (await localApiReachable()) {
    return new LocalApiPlatform()       // local API server running
  }
  return new WebPlatform()             // default: WASM in browser
}

export const platform = detectPlatform()

Adding a New Surface

To add a 4th surface (e.g., VS Code extension): create platform/vscode/index.ts, implement IPlatform using the VS Code extension messaging API, add detection logic in platform/index.ts. No React component needs to change.
