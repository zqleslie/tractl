React Frontend
One React codebase — three surfaces. Built with React 18, TypeScript, Zustand, and Vite.

Stack: React 18, TypeScript, Zustand (state), TanStack Query (async), Tabler Icons, Vite. No react-router — screen switching is URL-hash based with custom sync logic.

Directory Structure

src/app/
App root. Main router (App.tsx), theme sync, React context providers. Screen switching happens here based on URL hash.
src/screens/
Full-page views. FastStartScreen, WorkflowCanvasScreen, RequestEditor, RunHistoryScreen, EnvironmentManager. Each screen is a top-level route.
src/components/
Reusable components. Organised by domain: shell/, sidebar/, panels/, primitives/, results/, request-editor/, environment/. Never import from platform/ directly.
src/stores/
Zustand state stores. One store per domain: uiStore, workflowCanvasStore, executionStore, runHistoryStore, requestCollectionsStore, settingsStore, workspaceStore.
src/platform/
Surface adapters. The only place that knows which surface is running. Implements IPlatform for web (WASM), desktop (Wails), and localApi. Deep-dive →
src/types/
TypeScript types. workflow.ts, requestDef.ts, recent.ts, and other domain types. These mirror the Go structs in internal/spec — keep them in sync when the spec changes.
src/lib/
Utilities. tractlDocument (parsing/normalisation), requestEditor logic, fastStart templates, and other helpers that don't belong in stores or components.

Zustand Stores

StoreOwns
uiStoreActive screen, sidebar collapse, active tab IDs — pure UI state
workflowCanvasStoreDAG nodes, edges, selected node — canvas editor state
executionStoreCurrent run: running/done, per-step outcomes, assertion results
runHistoryStorePersisted list of past run results
requestCollectionsStoreSaved request collections — grouped sets of reusable HTTP requests
settingsStoreUser preferences: theme, editor settings
workspaceStoreWorkspace path, name, recent files
