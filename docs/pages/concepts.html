Key Differences That Trip JS Developers Up

Go maps are NOT safe for concurrent access ▼

In Node.js you never think about concurrent map access — there's only one thread. In Go, if two goroutines write to the same map[string]string simultaneously, the runtime panics with "concurrent map writes". That's why ExecutionContext wraps all its maps in a sync.RWMutex. This is not optional best practice — it's required for correctness.

Why goja instead of a Node.js/V8 binding? ▼

V8 is a C++ library. Embedding it into a Go program creates a large cross-compilation dependency — and you can't compile a WASM binary that contains another WASM runtime inside it. goja is a pure-Go ES5+ JavaScript engine: no C dependencies, cross-compiles to any target Go supports (including WASM), and is fast enough for small hook scripts. The tradeoff is no ES modules and limited ES2020+ features.

What does "no panic" mean in practice? ▼

Go's panic() is like an uncaught exception that unwinds the stack. In production Go servers you add a recover() middleware. traCtl's engine is designed to never panic in the critical path — every error lands in RunResult.ParseError, RunResult.ValidationError, etc. Exit code 2 means "something in the pipeline failed" — useful in CI to distinguish a broken config file from a failing test.

Go interfaces vs TypeScript interfaces — the key difference ▼

TypeScript uses structural typing but you still need to explicitly import and reference the interface type. Go interfaces are implicitly satisfied — if a struct has the right methods, it implements the interface automatically, with zero coupling between the struct and the interface definition. This is how the engine can accept mock implementations in tests without any changes to the production types.

Go modules vs npm packages — what's internal/? ▼

In Go, a directory named internal/ is enforced by the compiler — code inside it can only be imported by code in the same module (same go.mod). It's like private at the package level. The public SDK surface lives in pkg/ (importable by anyone). This is why you'll never see import "github.com/tractl/tractl/internal/engine" in a downstream project — the compiler rejects it.
